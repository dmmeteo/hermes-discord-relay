# Discord Relay 1.1.0 source candidate

This local release candidate adds opt-in receiver relay to the existing Discord
ownership plugin. Publication, profile installation, gateway restart, live guild
acceptance, and model completion have not been performed.

## Changes

- Separate exact sender/guild/thread relay routes with deny precedence.
- Explicit bounded single-hop envelope and persistent replay receipts.
- Native bot provenance and human authorization preserved through dispatch.
- One-send workflow using native tools, followed by a human-facing recipient
  report. Transport send success leaves admission unconfirmed.
- Discord Relay branding, with the existing install identity retained.

Use the [receiver and sender guide](../../README.md#configure-a-receiver) for the
schema, exact envelope, trust policy, limits, and delivery semantics.

## Compatibility and migration

The manifest remains `hermes-discord-thread-ownership`. The repository remains
`dmmeteo/hermes-discord-thread-ownership`. There is no new install directory,
repository rename, catalog entry, or landing-page URL.

Existing boolean and mapping ownership settings and the ownership env switch
are unchanged. Relay defaults off, including when only an `allow` list is
present. No ownership state migration is required. A relay-enabled profile
creates its receipt database on its first valid admission. Preserve that file
on update. There is no payload persistence or background receipt worker.

The source is verified against stock Hermes v0.22.0 commit
`e06df9c2eae6901f4c88f464e0ae6e753c0428b8`, using its native adapter and lifecycle.
Relay fails closed without the native bot hook and recovered-dispatch keyword.
Ownership keeps the existing compatibility behavior. Stock source remains
unchanged. The plugin adds no third-party dependency and retains the MIT license.

## Rollback

To stop relay while retaining ownership, set `discord.relay.enabled: false` in
the receiving profile on an authorized rollout and reconstruct the adapter by
restarting the gateway. To restore stock Discord, disable the plugin and restart
on an authorized rollout. No runtime action was taken by this source task.

The pre-relay source is `41c01d0f2efbddc7ba1881c40270459b351905c5`. Downgrading
source restores the previous ownership-only adapter. Remove the new relay block
when downgrading and keep the receipt database for a later re-enable. Do not
clear receipts to work around corruption or saturation without first resolving
fresh pending requests, because that discards replay protection.
